# Minimal RUNTIME requirements for the deployed Streamlit app (app.py),
# for Streamlit Community Cloud pinned to Python 3.12 (see runtime.txt
# at the repo root). This is NOT a `pip freeze` -- it lists only the
# direct top-level packages actually imported by app.py and its
# transitive src/ modules (agent.py -> escalation/evidence/generation/
# intent/retrieval), confirmed by inspecting every import in that graph.
#
# torch is pinned explicitly (2.14.0, no local version tag) because it's
# a real, direct runtime dependency of sentence-transformers, which this
# app needs at request time (retrieval/embeddings.py's get_model()) --
# not because app.py imports torch itself. The ORIGINAL deploy failure
# was `torch==2.14.0+cpu`: "+cpu" is a Windows-only local version tag
# with no matching Linux wheel on PyPI. Plain `torch==2.14.0` resolves
# to a normal Linux wheel under Python 3.12.
#
# transformers, scikit-learn, scipy, tokenizers, huggingface-hub,
# pandas, pyarrow, altair, etc. are transitive dependencies of the
# packages below (confirmed via `pip show` on each -- e.g. pyarrow comes
# in via streamlit's own dependency chain, not a direct import anywhere
# in this app's code) and are resolved by pip automatically; pinning
# them here would just be re-deriving a `pip freeze` by hand.
#
# Deliberately NOT included: Ollama support code's own extra deps (none
# -- LocalLLMClient only needs `requests`, already listed), and every
# test/evaluation/data-pipeline-only package (pytest, duckdb, datasets,
# matplotlib, scikit-learn as a DIRECT import, etc.) -- none of those
# are imported by the deployed app. requirements-dev.txt has the full
# local dev set (Windows, tests, evaluation) if you need that instead.
#
# ui/helpers.py has no third-party imports (stdlib only) and needs
# nothing added here.
